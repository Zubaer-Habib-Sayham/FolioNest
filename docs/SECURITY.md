# Security and privacy boundaries

- Guests keep drafts and resized photos in browser storage. Storage failure is surfaced; download a JSON backup before leaving. A shared device can expose its local draft to another person using the same browser profile.
- Optional portrait segmentation runs in a disposable local worker. A fetch guard installed before the pinned runtime loads permits only same-origin GET requests and suppresses its external diagnostics. Images are decoded locally; the saved normalized original is stripped from public data and exported assets. Browser checks exercise real segmentation, cancellation, failure and request isolation. Transparent PNG/WebP validation rejects metadata, animation, mismatched MIME signatures and malformed chunks. CSP permits WebAssembly compilation without general JavaScript evaluation.
- Express verifies bearer tokens with Supabase Auth, rejects anonymous accounts, derives the owner UUID and includes it in every private read/update/delete/publish/unpublish query. Client owner IDs are never trusted. Publishing uses an atomic expected-document comparison so concurrent edits cannot publish a different draft silently.
- All SQL parameters are bound. Every private endpoint validates identifiers, query keys and body shape. RLS separately restricts Supabase Data API reads; direct Data API writes are revoked. Privileged PostgreSQL connections can bypass RLS; owner predicates are the application boundary and are tested against real SQL, rather than relying on a claim that RLS protects the server connection.
- Public pages and APIs read only explicit publication snapshots and remove hidden content. A noindex page is still public. Publishing requires a specific confirmation and complete non-sample identity. Unpublishing clears the snapshot and excludes it from public routes and sitemap; search caches may take time to update.
- Zod strictly bounds fields, collection lengths, schemes, slugs, document size, raster bytes and dimensions. The renderer escapes structured text. User HTML, styles, SVG, scripts and remote image URLs are never accepted. Uploaded raster sources are decoded and recompressed locally, discarding original metadata. Backups carry the resized images.
- Express uses Helmet, a bounded JSON parser, exact origin checks, API no-store/noindex, process-local request limiting and safe centralized errors. PostgreSQL and Auth requests have timeouts. Logging contains only generated request IDs, method, matched route pattern, status and duration; no body, query values, credentials, slugs or content. Error logs contain error codes only.
- Database TLS certificate verification remains on. The database URL and passwords never enter the frontend. Supabase publishable keys and analytics project tokens are public by design; no elevated API key is required.
- Optional analytics is off by default, requires explicit consent and respects Do Not Track. The final send hook strips URLs, form data, person properties and all unknown properties/events. There is no replay, identity enrichment or automatic capture. Exported websites have no analytics dependency.
- Cloudflare's proxy accepts only a configured HTTPS upstream origin and forwards a narrow header set. It does not write files, operate a database or log request content. Static assets and robots bypass it. Never cache authenticated API responses or stale public snapshots at the edge.

Tests cover injected-account token failures, actual SQL ownership for five cross-account operations, strict API validation, RLS read isolation/direct-write denial, duplicate slugs, snapshot privacy, oversized bodies, origin/rate limits, text escaping and image rejection. Live token verification, SMTP, hosted TLS, edge-header behavior and abuse/load tests are still required before launch. Rate limits are process-local and may be shared by clients behind hosting proxies; they are not a distributed abuse-prevention guarantee.

Use a dedicated least-privilege database role when setting up production. Retain only the table permissions needed by Express and never grant browser roles direct writes. Rotate server credentials if exposed. Keep environment files, dumps and real user exports out of Git. Free-host quotas and account deletion/backup operations should be monitored by the site owner.
