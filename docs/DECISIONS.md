# Decisions

Six photographic designs adapt the supplied references through structured shared markup and CSS. The registry controls their allowed IDs, display-font inclusion and gallery metadata; the database check constraint is extended by a new transactional migration. Ownership, RLS and publication visibility are unchanged. Entrance/hover effects respect reduced motion; captured exports disable motion. Build-only female portrait variants supplement the established male model at the user's request. Choosing a gallery design never injects sample pictures into a saved draft.


Creative Studio's gallery now shows a fictional AI-generated portrait and two illustrative project covers in cream, charcoal and terracotta. Its transparent portrait uses the existing shared photo/circle composition, not a separate mockup. Optimized source assets are build-only; the gallery serves a flattened JPEG to limit loading cost. Selecting a design continues to preserve the visitor's text, photos and ordering. Prompts and asset provenance are documented in `assets/gallery/studio/README.md`.

The latest user request replaces the former text CV with Download résumé. It uses the same shared renderer with print-only composition for each template, retaining colors, fonts and visible photos on one A4 portrait sheet. A separate export copy keeps section/item order and visibility while progressively excerpting text and selecting leading records. Name and contact addresses remain intact; the saved draft is never rewritten. Body copy stays approximately 10.6 pt rather than shrinking an arbitrarily long page. Layout is measured before capture; content that still cannot fit produces actionable guidance instead of a clipped or multipage résumé. The PDF uses an approximately 288 DPI browser-rendered image and clickable link annotations. Its text is not selectable or tagged, so it is not intended as an automated résumé-parsing format. Portfolio PDF still exports the full visible content. Print at Actual size on A4.

Netlify Drop is the primary illustrated path for publishing an exported portfolio ZIP, with exact private-to-public and update steps, free-plan quota disclosure and built-in extraction fallback. Cloudflare Pages remains an alternative and the guide explains replacing an existing deployment with a fresh ZIP. This is separate from whole-application deployment, which still requires final product approval and live cloud verification. Provider instructions were checked against official documentation on 2026-10-11.

Studio now uses grid rows for its display title and portrait, removing the fixed-height absolute-position overlap. All preview-specific typography/layout overrides were removed. A named portfolio container, shared style rules and a 960-pixel desktop canvas now drive previews, exported pages and public HTML. Browser tests compare actual computed geometry/fonts for all five templates at matching desktop/mobile widths.

Portrait background removal is optional and runs in a disposable CPU worker using MediaPipe 1.1.0 and a pinned Selfie Segmenter v1 model served locally. Its external diagnostic transport is blocked before the runtime import. Only local assets can be fetched; the supplied image is decoded directly from its bounded data URI without a network request. Transparent WebP preserves resolution within the existing 96 KB image bound, with a bounded PNG fallback. The normalized original remains in private editing history for restoration and is stripped from public data and website assets. Signature images are optional in Studio; no typed signature is fabricated. The heavy runtime is copied from the pinned dependency for dev/build, fetched only when requested and excluded from portfolio ZIPs.

The user requested JavaScript in place of TypeScript. All tracked application, server, shared, proxy, scripts and tests now use JavaScript/JSX. React and the runtime Zod schemas remain; EJS would require a different rendering architecture. Esbuild handles Node-side JSX and the server build, and ESLint plus explicit JavaScript syntax validation replace the former TypeScript check. All five template HTML outputs were compared byte-for-byte before/after conversion and were identical. Existing unit/API and browser/export checks remain required. Earlier QA entries retain the commands actually used at that time.

The requested developer credit uses Zubaer Habib Sayham and the email supplied by the user. Gallery examples use that name, but work, qualifications and dates remain explicitly illustrative; they do not establish personal credentials. Names are the primary heading in every portfolio. Background choices are fixed, contrast-compatible light/dark pairs rather than user-supplied CSS. Existing version-one backups default to their previous background. The brand asset is displayed inside a tighter SVG viewport with a light badge, preserving the supplied artwork.

Choosing a gallery design applies that template to the existing local draft and saves the design choice, preserving the person’s text, photos and order. It never loads sample content implicitly. The hosting guide is for an exported static portfolio; FolioNest itself still requires the approved Express/Supabase deployment. PDF pages keep A4 dimensions and fill the complete page with the selected background; content keeps its internal layout padding, with no extra white export frame. Analytics adds only a fixed landing/builder visit enum, without URLs or private values; per-load IDs remain intentionally ephemeral.

- React/Vite and Express in npm workspaces with shared JavaScript runtime schemas and portfolio rendering. CSS variables provide a small consistent design system.
- One canonical schema bounds all text, lists, URLs, sections, fonts and palettes. Drafts may be incomplete; export/publish adds identity validation.
- Templates share structured content but differ in composition: editorial columns, bento grid, narrative bands and a career timeline.
- System fonts work offline. Optional portrait and project uploads accept bounded JPEG/PNG/WebP inputs, decode and recompress locally into JPEG without original metadata, and validate the resulting raster headers and dimensions on every save/import. No SVG, remote image URLs or arbitrary files are accepted. ZIP exports include local assets. Photos are part of the database JSON; a complete portfolio is limited to 2 MB.
- Drafts stay in browser storage until an explicit authenticated cloud action. Import requires validation and confirmation.
- Direct PostgreSQL uses owner predicates in every private query. RLS protects the Supabase Data API separately; privileged pg calls do not gain protection from those policies.
- Published content is a snapshot separate from drafts, so saving changes never silently publishes them.
- The server serves the built client and public HTML locally and may be deployed as one service. A small optional Pages proxy supports the specification's split-host arrangement.
- Analytics uses an explicit event/property allowlist, no automatic capture, page URL capture, identity, replay or personal data. It respects DNT and opt-out.
- Supplied build documents remain intact outside the application commits. Commits use the user's configured identity and verified slices are pushed to the existing FolioNest repository with authorization. Online deployment requires the user's final product review.
